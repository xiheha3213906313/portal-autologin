# 门户自动登录 1.2.4

为用户已验证的访客门户编写的 Android 应用，同时保留 LSPosed 传统 API 模块。目标门户与既有模块已在小米 14、Android 16 验证；新增普通应用流程仍需在未认证 Wi-Fi 上实测。

## 1.2.4 配置按钮与固定底部提示

- 未修改当前生效配置时按钮显示“当前配置”；切换到已保存账号且未修改凭据或模块开关时显示“切换配置”；新增账号或修改已有凭据、模块开关时显示“保存并登录”。当前已联网时仍留在配置页，按钮短暂显示“已联网”后恢复“当前配置”。
- 基础模式的 LSPosed 提示使用固定底栏，与登录结果页保持相同底部位置。底部安全间距只计算系统栏和刘海，不包含输入法；键盘弹出后覆盖底部提示，表单通过独立的 IME 间距继续避让键盘。
- 红色“确认”与“预设”统一使用 12sp，配置页和结果页共用提示文字组件。
- 版本升级为 1.2.4，versionCode 15，保持包名、签名与已有配置。

## 普通使用：无需 Root

1. 连接目标访客 Wi-Fi，打开应用。首次填写账号密码并保存，立即开始登录。
2. 已有配置时，启动应用或从后台返回前台，会检查当前 Wi-Fi。已通过系统联网验证就显示“已联网”，跳过账号提交；否则通过该 Wi-Fi 获取并严格检查目标门户页面，再提交一次认证。
3. 成功页面使用绿色勾的描边动效。相同 Wi-Fi 保持联网时，前后台切换保留页面，不重复提交、不重播成功动效。换网络或认证失效后会重新处理。
4. 底部“设置”可修改或清除账号。未连接 Wi-Fi、网络失败或账号未通过时可打开系统 Wi-Fi 面板、重试或返回设置。

登录结果页允许截图和最近任务预览；账号设置页继续启用防截图保护，避免账号出现在任务卡片里。设置页大标题右侧的灰色小字“关于”可查看应用版本、作者 xiheha，并打开公开项目地址：https://github.com/xiheha3213906313/portal-autologin 。

账号输入框右侧可展开 Miuix 账号列表。选择条目会同时填入账号和密码，再点击保存生效；相同账号再次保存会更新密码并移到前面。带名称的预设仅在列表显示名称且不可删除，自存条目右侧可删除；删除当前生效的自存账号时同时移除其自动登录配置。清除账号按钮保留内置预设。历史列表使用单独的本地私有首选项，不写入日志。

没有新增模式开关，不申请无障碍、定位、存储或 Root 权限。普通安装只显示账号和诊断设置；LSPosed 配置可用时保留原有模块开关。模块开关只控制原有后台认证/门户填表，打开应用时的普通登录直接由已保存的账号配置触发。

普通应用拥有 INTERNET、ACCESS_NETWORK_STATE 权限，请求严格绑定选中的 Wi-Fi，避免移动网络的联网状态被当作 Wi-Fi 认证成功。只有该 Wi-Fi 获得系统 VALIDATED 能力后才显示联网。只有本次目标门户认证请求已实际写完，随后同一 Wi-Fi 通过验证，才显示“登录成功”；普通已联网 Wi-Fi 显示“已联网”，不声称账号已认证。相同网络已确认的结果在前后台切换时保留。系统联网标记与账号会话状态不是同一个信息，当前没有门户会话查询接口；不把 HTTP 200/302、连接上 Wi-Fi 或提交前的防重试记录本身当作认证成功。

没有后台服务或永久网络监听。一次操作期间临时监听联网验证，成功、失败或最长 45 秒后注销；工作线程空闲 30 秒退出。无配置或已经联网时不启动认证工作线程。提交前记录 Network、开机次数和单调时间，在进程重建后仍阻止 5 分钟内重复提交；结果不确定时只检查联网状态，不重发。明确拒绝后允许修正账号再保存重试。

若同时使用 LSPosed 静默认证，应用通过签名权限保护的广播协调：后台已经开始 POST 时只等待结果，否则由应用暂时接管，防止两处并发提交。模块用户更新此版后需重启加载新的协调逻辑；普通用户无需重启。

诊断开关同时控制应用侧日志，导出时自动合并可用的系统模块日志。无 LSPosed 也能导出和清空应用日志，不要求系统日志连接。

显示版本为 1.2.4，versionCode 为 15；沿用原签名，可覆盖安装保留配置。新增普通流程已加入防重入、进程重启后的防重复提交、网络切换与明确拒绝后的重试测试；完整真机认证仍待验证。

## LSPosed 安装（可选）

1. 安装 `portal-autologin-1.2.4.apk`。
2. 在 LSPosed 中启用“门户自动登录”，作用域勾选“小米浏览器 / com.android.browser”。前台模式只需此作用域；实验静默模式还需勾选“系统框架 / android”并重启。已安装的 `com.android.captiveportallogin` 包不是本机实际宿主。
3. 重启手机一次，打开模块配置应用，填写自己的账号密码，打开开关并保存。
4. Wi-Fi 下次要求认证时打开系统登录通知，让登录页面留在前台。模块识别指定页面后自动逐字填写并点击 Login。
5. 实验静默模式：同时开启“自动登录”和“静默登录”并保存。未登录 Wi-Fi 出现 CAPTIVE_PORTAL 能力时才尝试后台认证。已认证时不强制注销。

## 0.4.4 保留前台自动填表兜底

开启“自动登录”后，前台填表始终可用，不再因为同时开启“静默登录”而跳过。静默失败或结束后，用户手动打开目标门户 Activity 时，会按已有流程逐字填写并自动点击 Login，不需要先关闭静默开关。

后台尝试进行时，已有系统层启动拦截仍对标准门户入口生效，直到失败、45 秒期限到达或系统验证成功；这次修改不会强制抢占正在执行的后台请求。前台流程在同一 Wi-Fi 已验证联网时立即停止，并保留单次提交、冷却、访问码/条款检查和离开前台暂停机制。如果系统存在绕过已有启动拦截的其他入口，不承诺对该额外入口跨进程串行化。

前台检查仍只在目标门户 Activity 的前台生命周期运行，平时没有新增轮询。此版本需重启加载系统和浏览器 Hook，自动填表兜底的组合行为仍需真机确认。

## 0.4.3 对齐成功的浏览器请求

用户提供的成功浏览器 POST 返回 HTTP/1.1 200，实际提交包含 `checkbox`、`checkbox1` 两个非空隐藏字段，并携带一个 Cookie。浏览器使用 Chrome 135 / XiaoMiBrowser 标识和文档导航请求头；此前后台请求的标识和请求头不完整。

- 仅对已确认的隐藏门户标志 checkbox / checkbox1，不再依赖原 HTML 的 checked 属性决定是否提交。保留每次获取页面中的 value，无 value 时使用 HTML 复选框默认的 on。可见条款或访问码仍需人工处理。
- 同步成功请求的 User-Agent、Accept、Accept-Language、Client Hints、Sec-Fetch、Cache-Control 和连接头。连接头恢复为成功请求中的 keep-alive；0.4.2 关闭连接未解决 EOF。
- Cookie 仍从本次 GET 响应建立，不预置或读取用户浏览器的 Cookie。诊断新增每阶段 Cookie 数量、Cookie 版本标记，及隐藏字段的缺失/空/非空状态（-1 / 0 / 1），不写入实际字段值。
- 保留提交响应不确定时的同 Wi-Fi 联网复测，不自动重发 POST。
- 0.4.3 已在小米 14 / Android 16 的目标访客 Wi-Fi 上验证后台认证成功：提交携带一个 Cookie 和两个隐藏标志，收到 HTTP 302，随后同一个 Network 获得 VALIDATED 并记录 `validated`，从尝试开始到验证完成约 2.2 秒。这个结果确认了当前设备和门户上的后台认证，不能单独归因于某一个字段或请求头的调整。

## 0.4.2 提交后连接关闭兼容处理

用户真机日志确认：两次 GET 均为 200，表单检查通过，POST 请求体写出，但读取响应时出现 IOException / EOFException，未收到 HTTP 状态码；稍后旧 Network 丢失、新 Network 验证通过，不能据此确认原请求认证成功。

- 所有请求设置 `Connection: close`，让准备页面和提交请求各自结束连接，排查网关连接复用兼容问题。此原因仍属待真机验证的假设。
- 保留固定长度流式 POST，不改为可重放的缓冲模式，不自动重新提交。
- 当请求体开始写入后出现 I/O 异常，记为 `submit.outcome_unknown`，仅触发相同 Wi-Fi 的系统联网复测，保持原 45 秒验证期限；结果由 VALIDATED 回调决定。收到明确认证拒绝仍按失败处理。
- 日志增加 `*.connection_close`、`submission.uncertain_waiting_validation` 和验证触发结果。不会把 EOF 当作成功或密码错误。
- 新增两个回归测试，覆盖响应 EOF 后不重发，以及写入前 TLS 失败不被算作已发送。独立连接策略和系统复测效果仍需用户设备验证。

## 0.4.1 诊断日志

在配置页打开“诊断日志”后即时生效，不必保存，也不会因此清除冷却或主动重试认证。开关默认关闭。日志只存在系统进程内存，保留最近 256 条，关闭开关停止新增记录，清空按钮删除现有记录，重启后旧记录消失。

导出流程：更新 APK → 打开诊断日志 → 重启加载新版系统框架 Hook → 在未认证 Wi-Fi 上复现一次 → 等待约 45 秒 → 点击“导出日志”，在系统文件选择器中保存 TXT。无需 Termux、Root 文件操作或存储权限。若提示系统日志未连接，检查系统框架作用域并重启。

记录网络能力标记（1=需要门户认证，2=已通过联网验证）、观察器/启动拦截状态、冷却、请求阶段、HTTP 状态码、响应大小、表单阶段、提交进度和最终验证结果。网络异常只记录异常类型及固定白名单原因码，不记录异常原文、堆栈、URL、IP、SSID、账号密码、Cookie、表单内容或响应正文。错误页面不能被当作自由文本写入日志。开关、导出和清空使用已有的签名权限保护广播通道，导出目标由用户选择。

诊断不会改变后台认证协议或绕过页面检查；用于确认 0.4.0 静默认证失败的具体阶段。系统进程重启后不会保留上一次的日志文件，只有用户主动导出时才写入所选文档。

## 0.4.0 实验静默模式

- 在系统框架作用域里，SystemServer 服务启动后注册 Wi-Fi 网络事件回调；无需打开浏览器或模块界面触发，没有常驻轮询、前台服务或通知保活。
- 工作线程通过对应 `Network.openConnection` 获取 `/index.html`、`leftFrame` 指向的 `/login.html` 和新 Cookie，再 POST `/login`。密码不做额外转换，复现已采集的 CheckSubmit 长度校验与 SetRedirectUrl 的 200 字符截取。保留服务器新生成的隐藏字段。
- 保持 HTTPS 证书验证，GET 重定向限定相同源，POST 之后不跟随跳转。每次最多提交一个请求，网络请求不运行在系统主线程上。
- 后台模式遇到可见访问码、条款、变化的字段或跨域表单时停止；无法从静态 HTML 证明控件隐藏时也停止。现阶段不执行外部 CSS/JS，网页变化时可关闭静默恢复前台模式。
- 在本次尝试期间，若能找到系统 ConnectivityService 的门户启动方法，则临时拦截对应 Network 的启动；失败或超过 45 秒自动放行。小米系统可能存在其他启动路径，因此此版本不保证任何设备上窗口都不闪现。日志 `launch_hooks_0` 或 `launch_hook_unavailable` 表示窗口抑制未接入。
- 提交后调用系统对相同 Wi-Fi 重新探测；只有网络具备 VALIDATED 能力才记录成功。HTTP 200 本身不代表登录成功。没有确认联网时回到手动登录路径，保留系统登录入口，不会绕过认证或关闭系统联网探测。
- 静默开关默认关闭。自 0.4.4 起开启静默不再停用前台自动填表兜底，标准门户入口在后台尝试期间仍由系统层暂时拦截；关闭静默开关则只保留前台模式。修改配置通过受签名权限保护的广播通知系统观察器。
- 每个 Network 至多一次尝试和 5 分钟冷却；网络消失或显式保存配置会重置该状态。认证 Cookie 仅存在于单次尝试内存中，用完清除。不记录账号密码或响应正文。
- 此版本完成协议单元测试、构建和 Lint；未在用户 Wi-Fi 实测后台认证、系统框架启动兼容性或登录窗口抑制。建议保留旧版 APK，先手动验证实验开关；不用静默时无需勾选系统框架。

配置页采用真正的 Miuix Compose 0.5.1 组件（MiuixTheme、TopAppBar、Card、TextField、SuperSwitch、TextButton、SuperDialog），跟随系统浅色/深色模式。主界面只保留账号、密码、两个开关、保存和清除账号。仅在未启用 LSPosed 或输入错误时显示提示。清除账号需二次确认；支持密码显示切换。

沿用 0.2.0 的登录流程、配置键、包名及签名，可覆盖安装。没有重新实现或修改自动登录逻辑。

## 0.2.0 加速更新

默认开启快速填写：字符间隔由 80ms 缩短到 8ms，焦点等待 30ms、每个字段失焦后 60ms、提交前等待 120ms；保留原有输入事件顺序。账号密码共 30 字符时，设置的输入流程等待总计约 540ms，不包含网页加载、系统调度和网关认证时间。配置页可关闭“快速填写”恢复原来的已验证速度。门户首次检查由 800ms 缩短为 150ms；仅在等待表单时每 400ms 检查，开始输入后恢复每秒检查。无独立后台服务。

0.1.0 已由用户在小米 14 / Android 16 上验证自动登录成功；0.2.0 的加速时序仍需实机验证。覆盖安装保持原有配置和签名。更新后重启浏览器进程或手机。

## 行为和限制

- 前台模式 Hook 限定 `com.android.browser` 内 `com.android.captiveportallogin.CaptivePortalLoginActivity` 的生命周期。
- JavaScript 同时验证 HTTPS 域名、1026 端口、同源 iframe、POST `/login`、输入框和按钮属于同一个表单。
- 沿用实机验证的逐字 beforeinput/input、change、blur、等待、按钮 click 流程。保留门户原有表单脚本和隐藏字段，不直接构造认证请求。
- 页面可见且准备就绪才开始。切到后台时暂停，交由用户手动完成，避免后台网页计时器造成不确定行为。
- 发现未勾选的可见复选框、空的可见访问码或表单校验失败时不提交。
- 每个文档只尝试一次，每个浏览器进程设 5 分钟冷却。进程被重启后冷却会重置；同一个会话加载新文档也不会自动再次提交。
- “已提交”不代表认证成功。仅当 Intent 提供了对应 Network，且该 Wi-Fi 具备系统 VALIDATED 能力时才提示联网验证通过。Intent 无 Network 或权限不可用时不声称验证成功。
- 浏览器前台 Hook 的网络行为仍通过浏览器门户完成；普通应用入口新增 INTERNET 和 ACCESS_NETWORK_STATE 权限，没有独立后台服务。

## 本地配置

账号密码与历史在应用私有 filesDir 固定保存，并同步到当前模式的 SharedPreferences；启用 LSPosed 后通过新 XSharedPreferences 支持的共享首选项供模块进程读取。这不是加密密码库。没有分析服务或凭据日志。账号只用于固定认证门户，以及用户主动确认的 GitHub 分享草稿；分享不会自动发出 Issue，最终由用户在 GitHub 发布。个人构建可内置用户提供的预设。配置页禁止截图和系统自动备份。设备 Root / LSPosed 环境中的其他高权限组件仍可访问本地配置。

修改配置后关闭并重新打开门户。关闭开关不会撤销已经提交的请求；正在输入时应关闭门户停止当前流程。删除配置按钮会清除保存的账号密码。

## 构建

使用 JDK 21、Gradle 8.11.1、Android SDK Platform 35、Build Tools 35.0.0、AGP 8.10.1、Kotlin / Compose Compiler 2.2.10、Miuix 0.5.1。Xposed API 82 jar 仅作编译桩，不打包。

1. 配置 `ANDROID_HOME` 或 `local.properties` 中的 `sdk.dir`。
2. 将 `https://api.xposed.info/de/robv/android/xposed/api/82/api-82.jar` 下载到 `toolchain/xposed.jar`。
3. 可选：在 `signing/module.p12` 放置签名密钥，口令保存于 `signing/password`，别名 `module`。未提供密钥时生成未签名 APK，需要签名后才能安装；自建密钥不能覆盖原发行版。私钥及口令不上传仓库。
4. 执行 `./gradlew :app:testReleaseUnitTest :app:assembleRelease :app:lintRelease`，或 `bash build.sh`。

JS 会在构建时生成 Java 常量；不要手工编辑生成文件。发布 APK 由 R8 缩减，保留 LSPosed Hook 入口。第三方组件通知和 Apache 2.0 协议放在 APK assets 中。

默认构建不包含个人预设。若需生成内置个人预设的安装包，将自备 JSON 文件放在已忽略的 `private-preset/private-account-presets.json`，格式为 `{"accounts":[{"label":"显示名称","username":"账号","password":"密码"}]}`，构建时显式增加 `-PincludeLocalAccountPreset=true`。该目录不进入源码归档或 Git；启用此参数生成的 APK 会包含这些预设。

LSPosed 新共享配置要求 API 93 支持（模块元数据 minversion 93）。
