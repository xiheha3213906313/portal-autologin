# 普通模式后台自动登录

普通模式的“后台自动登录”开关即时保存并启动或停止用户可见的前台服务，使用已保存的登录账号。尚未保存账号时明确提示先保存账号和密码。通知只显示简短状态，不包含操作按钮；点击通知可以打开软件。Wi-Fi 名称在结束编辑、输入法关闭或打开授权卡片时保存，输入法关闭后输入框自动失焦。

Wi-Fi 名称为空时接受全部 Wi-Fi 连接。非空时，对完整名称进行 NFKC、大小写、空格和标点标准化后比较，不使用包含匹配；例如 `Guest-WiFi` 匹配 `guest_wifi`，`Guest1` 不匹配 `Guest10`。只有标点的条件会被拒绝。非空条件读取不到名称时保持不匹配，不会退化为匹配全部。

## 触发与认证

- 使用 Wi-Fi 的 NetworkCallback，等待地址和 DNS 可用后进行一次防抖检查，不定时轮询。
- 前台界面和后台服务共用 AppLoginController；前台操作优先，不并行提交不同网络的认证。后台加入同一网络的前台纯联网检查时，沿用正在执行的检查，并在失败后接续认证；已开始提交凭据的任务只合并等待，不重新提交。只有本次实际接手的任务失败会清除待重查事件，后续无关的前台失败不会清除；前台新的真实联网成功可恢复失败后的监测，但仍保留已捕获的网络变化。
- 每个被接受的后台连接事件都重新验证选中的 Wi-Fi，不复用此前成功记录。未开启强制登录时，后台一律先探测互联网；实际无法上网才尝试门户认证，避免系统标记不准确或旧缓存影响流程。
- “强制登录”在后台连接检查时也会跳过系统联网标记，但自动后台事件仍遵守提交记录冷却，避免重复提交结果未知的 POST。
- 每次连接合并重复事件。认证失败不会被能力标记的反复变化自动重试；重新连接、用户操作或更改配置可重新触发。已联网后再次收到门户认证信号或丢失系统已验证标记，允许进行新的检查；即使状态在防抖期间恢复，也不丢失这次待检查事件。30 秒检查间隔内的真实变化只排队一次，到期后检查，不通过重复回调持续轮询。
- 所有认证和联网验证绑定选中的 Wi-Fi；不会用移动数据的联网结果替代。多个 Wi-Fi 网络由同一控制器协调处理。
- 只有检查期间持有最多 60 秒的 CPU 唤醒锁；结束、断开或停止服务会释放。空闲时不持有唤醒锁。

## 权限和运行条件

- Wi-Fi 名称输入框右侧提供“授权”卡片，返回应用后刷新授权状态，不轮询权限。
- 必选授权分组提供通知、自启动设置入口，以及指定名称时所需的精确定位与系统定位开关。开启后台功能时展示屏幕中央的配置卡片，同时列出通知权限和自启动权限，通知未授权时及自启动项提供“去授权”按钮，通知已授权时显示“已授权”。用户点击“我已授权”即可直接记录配置完成并关闭卡片；完成后再次开启、保存配置或重启应用都不再自动弹出该卡片，不再要求设置页返回检测；完整授权列表仅从输入框右侧“授权”打开；后台服务以系统实际通知与必要定位授权为启动条件；自启动属于设置引导，不再通过手动确认标记阻止服务启动。系统本身并不把通知权限作为启动前台服务的必备条件，这是本应用的启用规则。
- 同时检查应用通知总开关与后台自动登录通知渠道。通知请求立即显示，避免前台服务通知被系统短暂延迟；不绕过用户关闭通知的选择。
- 非空 Wi-Fi 名称条件需要精确定位权限、系统定位开关及 location 前台服务类型，以在界面退到后台后读取 SSID。不获取定位坐标。
- 空名称条件不读取 SSID，不请求定位权限。服务采用 specialUse 类型，声明了具体用途。
- 服务从用户可见的界面启动。系统允许时进行粘性恢复；运行条件不足时暂停或停止，重新打开应用会检查已保存设置并恢复。
- 未加入开机广播自动启动。系统强行停止、厂商后台限制仍可能中断运行，因此界面标记为实验性功能。
- 自启动列入必选项，优先跳转品牌对应的管理页，不支持时退到应用信息。系统没有统一的自启动授权查询接口，配置完成由用户在中央卡片中点击“我已授权”确认；不冒充系统自动检测。完整授权列表中的自启动始终显示“去设置”，点击直接跳转，不显示“已确认”，也不额外弹通知或自启动确认卡片。电池优化豁免和无障碍辅助列为可选项。电池优化状态不代表厂商全部后台限制已解除。
- 无障碍辅助仅在系统连接服务时，尝试恢复已保存并开启的后台自动登录；不读取窗口、不接收界面事件、不模拟操作，也不定时唤醒。不会替代前台服务，不保证保活；缺少后台定位使用条件时仍需重新打开应用恢复指定名称监听。
- 从授权设置返回或重复启动相同后台配置，不重置当前连接的检查记录；授权恢复只刷新通知，不重复提交认证。
- 小米系启用 LSPosed 模块时使用现有模块路径，不同时运行普通模式的后台服务。
- 1.4.1 起模块可用性由真实框架服务连接及断开事件提供，界面和服务共用该状态，不再探测世界可读偏好；框架服务稍晚连接时重新检查模式。配置保留与同步见 [Modern Xposed 迁移](modern-xposed.md)。

Android 依据：[WifiInfo](https://developer.android.com/reference/android/net/wifi/WifiInfo)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[前台服务启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。

## 真机检查

| 场景 | 预期 |
| --- | --- |
| 已有登录账号，条件留空，开启后台开关并退到后台 | 通知显示简单状态，没有按钮；不请求定位权限 |
| 输入 `Guest-WiFi`，连接 `guest_wifi` | 匹配并检查；保存和重新启动后条件仍保留 |
| 输入 `Guest1`，连接 `Guest10` | 不触发后台认证 |
| 指定名称但拒绝精确定位或关闭系统定位 | 暂停匹配，界面提供授权入口；不会匹配全部网络 |
| 连接未认证的目标 Wi-Fi，移动数据保持开启 | 通过该 Wi-Fi 提交和验证，移动数据不能带来“已联网”结果 |
| 系统报告已验证，但实际被门户拦截 | 后台检查后尝试认证 |
| 已正确联网 | 显示“已联网”；开启强制登录时尝试门户，门户关闭后验证互联网 |
| 重复收到网络能力、DNS、地址变化事件 | 合并同一连接的检查，不连续提交 |
| 密码错误或 POST 结果未知 | 保留失败或验证状态，后台不循环提交 |
| 前台登录过程中收到后台事件，或同时出现两个 Wi-Fi | 共用控制器协调处理，前台任务优先 |
| 屏幕关闭后连接、断开并重连 Wi-Fi | 服务在系统允许的条件下工作；无永久唤醒锁 |
| 关闭开关、删除当前账号或清空配置 | 服务和通知停止，已排队的旧回调不恢复监听 |
| 撤销权限、系统停止进程后重新打开应用 | 重新检查条件，恢复服务或显示授权说明，不崩溃、不扩大匹配范围 |
| 授予通知但关闭后台自动登录通知渠道 | 授权卡片仍提示去授权，跳转渠道设置；返回后更新状态 |
| 从授权设置重复返回，配置和网络未变 | 刷新服务通知，保留认证去重记录 |
| 打开或关闭诊断日志 | 仅开启时显示导出日志和清空日志 |
| 自启动、厂商电源策略 | 提供设置入口，不把跳转设置等同于授权成功 |
| 选择启用无障碍辅助 | 系统接入时尝试恢复已启用的后台功能；不读取界面，未启用后台登录时不启动监听 |

## 退出与通知

- 后台功能开启时，在页面正常返回退出的位置，将当前任务排除出最近任务并退到后台；重新打开应用时恢复任务可见性。服务声明 `stopWithTask=false`，隐藏界面不停止服务。设置页、弹窗的返回仍先关闭当前页面或弹窗。
- 任务隐藏不保证厂商不杀进程；未配置或未完成必选授权时，即使界面退到后台也不会进行认证。
- 常驻通知使用前台服务、`setOngoing(true)`、服务分类和 `setAutoCancel(false)`，不带按钮。Android 14 起用户仍可单独划掉这类通知；不伪装通话或媒体通知，也不使用定时重发来对抗用户操作。通知划掉和服务停止分别记录，网络状态实际变化时仍可正常更新通知。
- 开关标题后的灰色状态区分“未配置”“未授权”“运行中”“未运行”；关闭开关时隐藏状态。必选、可选授权各自使用 Miuix 原生 Card 和主题容器背景色，不手工描边。Wi-Fi 输入框提示为 `Wi-Fi名称(留空匹配全部)`。

## 启动诊断

开启日志和导出时都会记录已保存的后台开关、服务是否运行、启动是否待处理、通知能否显示，以及启动前提检查结果。不记录 Wi-Fi 名称或账号内容。

`background.readiness` / `background.sync` / `background.start_blocked` 的数值：0 可启动，1 正在使用受支持的 LSPosed 模式，2 后台开关未开启，3 未保存账号，4 Wi-Fi 名称无效，5 缺少精确定位授权，6 系统定位未开启，7 通知未开启。`background.start_requested` 后若没有 `background.started`，可结合启动失败与异常类型记录继续排查，不再将通知授权等同于服务已启动。

新增检查：已有账号时直接开启后台开关，不点击主保存按钮，也应出现服务启动记录和通知；输入法首次弹出不应立刻失焦，点击完成或手动收起输入法应失焦并保存名称；拒绝定位时应显示具体原因；后续授权完成后自动恢复，保持原先的连接去重记录。

补充真机检查：首次开启时展示包含通知及自启动两项的中央卡片，点击对应的去授权打开系统权限或设置页；通知授权通过后，不因未点击“我已授权”而保持“未授权”；没有已保存账号时优先显示“未配置”；系统无自启动开关时可明确确认无需设置；返回退出后最近任务隐藏，点击桌面图标或通知仍能重新打开；划掉通知后导出日志，分别检查 `background.running` 与 `background.notification_present`，不把通知消失当成服务停止。

Android 14 通知行为依据：https://developer.android.com/about/versions/14/behavior-changes-all#non-dismissable-notifications

中央权限提示检查：开启开关不自动展开完整授权列表，中央卡片同时显示“通知权限”和“自启动权限”；通知授权后实时显示“已授权”，自启动仍显示“去授权”。系统权限或设置页返回后仍保留中央卡片，“我已授权”按钮不设置返回检测门槛，点击后立即持久化 `background_setup_completed` 并关闭卡片；该记录只决定后续是否再弹提示，不作为服务授权条件。真实通知、定位权限仍由系统检测，用户确认不会伪造系统授权。完整授权列表中的自启动始终显示“去设置”，直接打开系统设置，不再弹额外卡片。旋转屏幕或系统重建 Activity 后恢复当前配置卡片。必选与可选列表使用 Miuix 原生卡片形状与配色，兼容浅色和深色主题。

完成记录检查：点击“我已授权”后，关闭再开启后台开关不弹卡片，应用重启后同样不再弹；保存配置不绕过该完成记录重复弹窗。没有完成记录时，取消卡片后下次开启仍显示。通知授权结果返回时立即刷新“已授权”状态；真实权限被撤销时继续使用真实授权状态进行服务启动检查。

通知通过检查：未点击“我已授权”时，授予通知后仍能通过启动前提检查；配置与实际定位条件齐备时启动服务。自启动引导及提示卡片的完成记录不参与“未授权”的判断；指定名称时仍须有真实精确定位授权并开启系统定位。

## 后台漏检修复检查

- 连接或重连后，`background.triggered` 后应出现 `app.background_check`；未开启强制登录时出现 `app.background_verify_first`，通过当前 Wi-Fi 重新检查，不能仅复用旧“已联网”结果。
- 已联网后在同一连接上丢失 VALIDATED、出现 CAPTIVE，或两者在 800ms 防抖期间快速恢复，都应保留一次重查。若距上次检查不足 30 秒，记录 `background.recheck_deferred` 及剩余毫秒数，只安排一个有事件依据的延迟任务。
- 失败、密码错误或提交结果未知后不因网络能力反复变化自动重发 POST；现有 15 秒失败冷却和 5 分钟提交记录仍生效。
- 网络回调增加 available、capabilities、link_ready、lost 记录；能力位 2 为 VALIDATED，1 为 CAPTIVE；link_ready 位 1 为有地址，2 为有 DNS。所有记录均不含 SSID、IP 或凭据。
- 未进入检查时记录 waiting_capabilities、waiting_link、waiting_address、waiting_dns、network_unsuitable、filter_skipped、controller_wait、already_checked，便于区分实际等待、匹配失败与重复事件合并。
- 真机验证：提前开启诊断日志，退到后台后连接仍需认证的访客 Wi-Fi；检查是否无需打开应用即可联网。另测已联网重连、同一连接认证过期、前后台同时检查、快速标记变化以及错误密码不会循环提交。
