# 在线预设

共享文件为 `release-assets/account-presets.json`，应用通过 `api.github.com` 的 GitHub Contents API 读取本仓库 `main` 文件内容，不依赖某一版本标签或 Release。请求使用 `application/vnd.github.raw+json`，直接在 API 域名取得文件正文，不跳转到 raw 域名；连接和读取超时各保持 5 秒。维护者修改并推送该文件后，用户点击账号列表中“使用其他账号”右侧的刷新图标即可获取，无需再次更新 APK。首次使用此功能仍需安装具备在线预设功能的版本。

文件是公开分发的预设数据，仅录入已获得公开授权的配置。当前包含此前已批准公开发布的两条预设，以及三条标注“测试”的模拟配置。测试项仅用于验证在线刷新和选择，不能用于真实 Wi-Fi 认证；验证完成后可从此文件撤下。功能不会上传用户自存账号、密码或当前配置。

格式如下，示例值不是实际账号：

```json
{
  "version": 1,
  "accounts": [
    {"label": "示例地点", "username": "example-user", "password": "example-password"}
  ]
}
```

- `version` 是根结构的格式版本，目前为数字 1，与应用版本、内容更新次数无关。增加普通可选字段时继续保持 1，不改名或删除原有 `accounts` 数组及当前条目的必需字段。
- 每条的 `label`、`username`、`password` 必须是非空字符串，账号不可重复。显示名最长 80 字符，账号和密码各不超过 4096 字符，不接受控制字符；密码保留原有空格与特殊字符。
- 当前门户最多 200 条，其他门户的条目不占这个数量；整份下载仍最多 256 KiB。使用 HTTPS GET，不跟随重定向；当前门户条目格式错误、过大、非 UTF-8 或获取失败时不导入。
- 成功后短暂显示“已获取最新预设”，随后恢复“使用其他账号”；失败短暂显示“获取失败，请重试”。请求过程中禁止重复点击。
- 刷新可更新已有预设的名称、密码及增删条目，自存账号与相对顺序保持不变。同名的自存账号优先，不被远端值覆盖。预设在列表底部显示，仍不可由用户删除。
- 当前正在使用或编辑的账密不自动切换，不触发登录；需要使用更新后的账号时从列表选择，再保存。若原配置已不匹配最新预设，则不再把旧账密标为只读预设。
- 已下载内容和账号列表一起保存在应用私有配置中，重开应用或离线时继续使用最后一次成功获取的预设。已有远端缓存时优先使用缓存，安装包内的旧预设不会把它覆盖回去。空 `accounts` 表示撤下全部远端预设，自存账号与当前登录配置仍保留。

读取与导入的诊断只记录阶段、是否成功及条目数量，不记录文件正文或账密。未来新增公开账号需单独取得对应授权，不能把既有预设的公开授权扩大到用户私有配置。

## 新字段与未来门户兼容

根对象和账号对象中不认识的普通字段会忽略，不影响读取既有字段。预留两个可选的分派字段：

- `portalId`：稳定且区分大小写的门户标识，当前仅支持 `bytedance`。旧条目不写时按当前门户处理；显式写入未知、空或非字符串标识时跳过，不退回当前门户。
- `schemaVersion`：单条账号结构的格式版本，省略时为数字 1。高版本或无法识别的值跳过，允许将未来不同认证结构的条目与当前兼容条目放在同一文件。

识别门户和条目结构发生在读取账密之前，所以其他门户即便使用同名账号或不同必需字段，也不会污染当前门户或导致当前条目重复。只有当前可用条目参与校验、去重及缓存；缓存会为旧条目补写当前门户及结构标记。不缓存未知字段和其他门户条目。

非空数组若全是未知门户或不支持的结构，本次不导入，保留最后可用的预设；不能把“没有识别到可用条目”当作删除当前预设的指令。明确的空 `accounts: []` 仍保留原有撤下语义。当前可用条目本身损坏或重复时，整次更新失败并保留旧缓存。

未来只增加展示或辅助字段时保持根 `version: 1`；若条目改变认证含义或必需结构，使用新 `portalId` 或提高该条目的 `schemaVersion`，并继续提供旧客户端能识别的当前门户条目。若确实重构根结构，则需另留兼容文件或接口，不能要求旧客户端猜测新格式。

这次只准备字段解析边界，不实现其他门户的认证、选择界面或本地配置隔离。已经安装的旧测试包不能远程改变解析逻辑，需要先升级到具备这些规则的版本，之后再按此约定扩展文件。
